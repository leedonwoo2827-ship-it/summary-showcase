# 매뉴얼 — 한 챕터를 끝까지 만드는 여덟 걸음

원고를 받아 유튜브에 올릴 영상까지 가는 길. **괄호 안은 앱이 하는 일**이다 —
누르고 기다리면 된다. 괄호 밖이 사람이 눈으로 보고 정하는 자리다.

```
1  원고 HTML 넣기            → (구조 읽기)  ★ 길이를 여기서 확인한다
2  목차 — 순서·제목 확정                    표지·마무리는 「+썸네일」로
3  (그림 지시문)                          → 09_이미지 에 JSON 두 개
4  (이미지·썸네일 JSON 만들기)
   4.2  다른 에이전트에서 그림 받기          번호로 09_이미지 에 넣는다
5  (덱 전체 · 자막 대본 생성)             화면에 보이는 원문
   5.2  (발음 대본 생성)                  그 자막을 소리 나는 대로
6  (덱 전체 · 음성/자막 굽기)
7  (영상 렌더링)
   7.2  장별로 듣기 — 발음 고치고 OK
   7.3  마스킹 — zone 지정 → (클로드가 차례 세팅)
   7.4  (영상 다시 렌더링)                 ★ 발음을 고쳤을 때만
8  (모션 전체 굽기)                        유튜브 글 복사해 올리고 최종 청취
```

---

## 1 · 원고 HTML 넣기

좌측 메뉴 **수정 — 유형 → + 원고 HTML**

> 📷 _캡처 자리 — 원고 HTML 화면_

원고의 `data-say` 가 **그대로 강의 내레이션이 된다.** 넣는 순간 앱이 길이를
말한다.

```
원고 대본 32장 · 6,100자 → 약 18.6분
```

★ **여기가 되돌리기 가장 싼 자리다.** 짧으면 지금 되돌린다. 그림·음성·영상을
만든 뒤에 알면 전부 다시 해야 한다 — 20장이 6분으로 나와 실제로 되돌렸다.

원고 맨 위에 `<!-- 20장 · 목표 15~20분 -->` 이 있으면 목표와 견준다.
분량 기준은 [02-원고-보내실-때.md](02-원고-보내실-때.md).

| 목표 | 공백 뺀 `data-say` 합계 |
|---|---|
| 15분 | 약 5,000자 |
| 20분 | 약 6,600자 |

## 2 · 목차 — 순서·제목 확정

좌측 메뉴 **목차**

> 📷 _캡처 자리 — 목차 화면_

- 순서 바꾸기 · 제목 고치기 · 빈 장 끼우기
- **표지(1장)와 마무리(맨 끝)는 `+썸네일`** 로 둔다 — 그림이 화면을 꽉 채운다
- 끝나면 **「이 목차로 확정」**

★ **목차가 앞인 것이 핵심이다.** 지금 고치면 공짜고, 확정한 뒤에 고치면
문구·판단·대본·음성을 전부 다시 돌려야 한다.

## 3 · 그림 지시문

현황판 → **그림 지시문**  ·  Claude 를 부른다(~$1)

> 📷 _캡처 자리 — 현황판의 그림 지시문_

장마다 그림 프롬프트를 쓴다. 라벨 개수는 **그 장의 내레이션 길이**로 정해진다
(`want_n(say)`) — 40초짜리 장에 라벨 3~5개다.

## 4 · 이미지·썸네일 JSON

**+ 원고 HTML** 화면 → **「이미지 JSON 만들기」**

> 📷 _캡처 자리 — 이미지 JSON 만들기 단추_

`09_이미지/` 에 파일 둘이 나온다.

```
이미지프롬프트.json      본문 슬라이드 — 3:2 플랫 벡터
썸네일프롬프트.json      표지·마무리 — 16:9. 봉투가 다르다
```

### 4.2 · 다른 에이전트에서 그림 받기

두 앱을 코드로 잇지 않는다. **접점은 `09_이미지/` 폴더 하나다.**
받은 PNG 를 슬라이드 번호로 넣는다(`002.png`, `003.png` …).

바탕색 지시는 [03-이미지프롬프트-바탕색-쪽지.md](03-이미지프롬프트-바탕색-쪽지.md).

> 📷 _캡처 자리 — 그림이 다 들어온 09_이미지 폴더_

## 5 · 자막 대본 생성

덱 → **(전체) 자막 대본 생성**

> 📷 _캡처 자리 — 덱 상단의 전체 굽기 단추들_

화면에 보이는 원문을 만든다. **원고가 대본을 들고 왔으면 그대로 쓴다 —
공짜다.** Claude 는 원고가 없는 장에서만 부른다.

### 5.2 · 발음 대본 생성

덱 → **(전체) 발음 대본 생성**  ·  몇 초 · 공짜

★ **왜 갈랐나.** 손이 가는 순서가 「자막을 읽고 고친다 → 그 자막대로 발음을
만든다」이기 때문이다. 한 번에 만들면 자막을 고쳐도 발음은 옛 자막에서 나온
채로 남는다 — 20장에서 실제로 그랬다.

Claude 를 안 부르는 결정론이라 **자막을 고칠 때마다 다시 눌러도 손해가 없다.**
네 가지를 한다.

```
괄호   국내총생산(GDP)은  →  국내총생산은
어미   늘었다             →  늘었습니다        (이미 높임이면 안 건드림)
숫자   1929년 1,040억     →  천구백이십구 년 천사십 억
기호   250%               →  이백오십 퍼센트
```

손으로 고쳐 둔 발음이 있으면 **몇 장이 덮이는지 먼저 말하고 묻는다.**
자막은 건드리지 않는다 — 그것이 이 변환의 재료다.

원고가 `data-read` 를 실어 보내도 쓰지 않는다. 그쪽 발음은 길이를 재려고 만든
것이라 규칙이 다를 수 있고, 출처가 둘이면 어느 쪽이 소리로 나갔는지 알 수 없다.

## 7 · 영상 렌더링

좌측 메뉴 **영상 렌더링** → **(전체) 영상 렌더**

> 📷 _캡처 자리 — 영상 렌더링 화면_

`11_완성/<slug>.mp4` 가 나온다.

★ **듣기·마스킹보다 렌더링이 먼저인 이유** — 마스킹이 쓰는 스틸이 mp4 에서
나온다. 슬라이드 PNG 는 렌더링 중에만 있다가 지워진다
(`pipeline/s12_video.py:149`). 영상이 없으면 상자를 얹을 그림이 없다.

### 7.2 · 장별로 듣기 — 발음 고치고 OK

덱 → 상단의 **장 번호 탭**

> 📷 _캡처 자리 — 장별 화면의 음성 줄_

```
음성  ▶ ━━━━━━━━  [✦ 자막에서 발음 만들기]  [↻ 발음대로 다시 합성]
자막 (화면에 보이는 원문)   │   발음 (TTS 입력 · 실제로 읽는 텍스트)
                          │   [✦ 숫자를 소리대로]
```

| 단추 | 무엇 |
|---|---|
| 자막에서 발음 만들기 | 자막을 재료로 발음 대본을 **그 장만** 다시 만든다 |
| 숫자를 소리대로 | `1960년대` → `천구백육십 년대` · `2.0` → `이 쩜 영` |
| 발음대로 다시 합성 | **그 장만** 다시 만든다. 전체를 안 돌린다 |

★ **발음 칸은 「발음대로 적는 자리」다.** 맞춤법을 지키는 자리가 아니다.
자막은 원문 그대로 두고, 여기에는 **소리 나는 대로** 적는다 — 그러라고 칸을
둘로 나눠 놓았다.

```
자막   실질 GDP 는 2.0퍼센트 늘었습니다      ← 화면에 박히는 글
발음   실찔 지디피 는 이 쩜 영 퍼센트 늘었습니다   ← 소리 나는 대로
```

TTS 가 「센다는」을 「쎈다는」으로 읽는 것 같은 일이 있다. 규칙이 아니라 모델이
배운 습관이라 끄는 스위치가 없으니, **여기에 원하는 소리를 적어서 잡는다.**

반복되는 것은 `voicewright/config/pronunciation_map.yaml` 에 올린다.
서버를 다시 켤 필요 없고, **자막에는 적용되지 않는다** — 화면 글은 늘 원문이다.

### 7.3 · 마스킹 — zone 지정

같은 장별 화면, 음성 아래

> 📷 _캡처 자리 — 스토리보드_

```
[지정기 만들고 열기]   새 창에서 상자 찍기 → zones.json 내려받기
[zones.json 넣기]      받은 파일 고르기 — 몇 개 바뀌는지 물어본다
[전체] 차례 잡기        상자를 읽어 말하는 차례에 맞춘다 (몇 분 · $2~3)
장을 훑는다             「시각 다 있음」 확인 · 이상한 줄만 끌어 고치기
[정리됨 · 저장]         누르면 다음 장으로 넘어간다
```

★ **처음 한 번은 「지정기 만들고 열기」를 눌러야 한다.** 스틸이 그때 뽑힌다.

★ **상자 차례는 화면 위치가 아니라 말하는 차례다.** 19장은 31장 중 25장이
상자를 좌우로 두어, 위→아래 정렬로는 차례가 정해지지 않았다. 그래서 앱이
상자 안 글자를 읽어 대본과 맞춘다.

★ 저장은 **장 하나씩** 간다. 모션 화면의 「zones.json 불러오기」는 파일을
통째로 갈아 끼운다 — 2026-08-16 에 그렇게 시각 186개가 날아갔다.

### 7.4 · 영상 다시 렌더링

발음을 하나라도 고쳤으면 다시 굽는다. 안 고쳤으면 건너뛴다.

★ 모션은 **완성 mp4 의 오디오를 그대로 복사한다**(`-c:a copy`). 옛 mp4 위에
모션을 얹으면 고친 장만 옛 발음으로 남는다.

## 8 · 모션 전체 굽기

좌측 메뉴 **모션** → **전체 굽기**  ·  35~43분

> 📷 _캡처 자리 — 모션 화면_

글자가 말하는 차례대로 떠오르고 빛이 훑는 판을 다시 굽는다. 원본 길이의
1.5~1.8배가 걸린다. 값을 바꿔 보고 싶을 때만 **시안 95초**를 먼저 굽는다(2분).

끝나면 **유튜브에 올릴 글**을 복사해 올리고, 마지막으로 통째로 들어 본다.

> 📷 _캡처 자리 — 유튜브에 올릴 글_

## 막혔을 때

| 증상 | 왜 |
|---|---|
| 스토리보드가 안 보인다 | 영상을 아직 안 구웠다. 7번 먼저 |
| 상자를 찍었는데 그림이 없다 | 「지정기 만들고 열기」를 한 번도 안 눌렀다 |
| 고친 발음이 안 먹는다 | 그 장 오버라이드에 옛 글이 있다 — 「자막에서 발음 만들기」 |
| 파이썬을 고쳤는데 그대로다 | `run.bat` 에 `--reload` 가 없다. 서버를 껐다 켠다 |
| 대본이 짧게 나왔다 | 원고 `data-say` 가 비었다. 1번으로 돌아간다 |
