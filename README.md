# 개발자 프레젠트 지원 에이전트

레포 폴더 + 화면 녹화 + 라이브 URL 을 넣으면 **20~40장짜리 발표 덱**이 나옵니다.
장마다 내레이션 음성이 붙고, 몇 장에는 영상이 임베드됩니다.

이 툴이 파는 것은 콘텐츠가 아니라 **기획**입니다. 개발자는 재료를 이미 갖고 있고,
없는 것은 그걸 발표물로 구성할 시간입니다.

```
setup.bat        (mac: ./setup.sh)     처음 한 번
run.bat          (mac: ./run.sh)       → http://localhost:5178
```

**API 키가 필요 없습니다.** Claude Code 구독 로그인을 그대로 씁니다.
터미널에서 `claude` 를 한 번 실행해 로그인해 두면 됩니다.

## 사람이 하는 여덟 걸음

아래 파이프라인 표는 **기계가 도는 순서**입니다. 사람 손이 실제로 가는 자리는
여덟 군데뿐이고, 그 사이는 앱이 알아서 갑니다.

**괄호 안은 앱이 하는 일**입니다 — 누르고 기다리면 됩니다.
괄호 밖이 사람이 눈으로 보고 정하는 자리입니다.

```
1  원고 HTML 넣기            → (구조 읽기)  ★ 길이를 여기서 확인한다
2  목차 — 순서·제목 확정                    표지·마무리는 「+썸네일」로
3  (그림 지시문)                          → 09_이미지 에 JSON 두 개
4  (이미지·썸네일 JSON 만들기)
   4.2  다른 에이전트에서 그림 받기          번호로 09_이미지 에 넣는다
5  (덱 전체 · 발음 대본 굽기)
6  (덱 전체 · 음성/자막 굽기)
7  (영상 렌더링)
   7.2  장별로 듣기 — 발음 고치고 OK
   7.3  마스킹 — zone 지정 → (클로드가 차례 세팅)
   7.4  (영상 다시 렌더링)                 ★ 발음을 고쳤을 때만
8  (모션 전체 굽기)                        유튜브 글 복사해 올리고 최종 청취
```

### 되돌리기가 싼 자리는 앞쪽입니다

★ **1번에서 길이를 봅니다.** 원고의 `data-say` 가 그대로 내레이션이 되는데,
예전에는 음성을 구운 뒤에야 짧은 것을 알았습니다. 20장이 6분으로 나와 되돌렸고,
19장이 초기에 5분대였던 것도 같은 일이었습니다. 지금은 원고를 넣는 순간
「원고 대본 32장 · 6,100자 → 약 18.6분」을 말합니다.

원고 맨 위에 `<!-- 20장 · 목표 15~20분 -->` 이 있으면 목표와 견줍니다.
분량 기준은 [docs/원고-보내실-때.md](docs/원고-보내실-때.md) 에 있습니다.

★ **듣기·마스킹이 렌더링 뒤에 오는 이유.** 음성은 6번에서 이미 나오니 렌더링
없이도 들을 수 있습니다. 그래도 7.1 을 먼저 돌립니다 — **마스킹이 쓰는 스틸이
mp4 에서 나오기 때문**입니다. 슬라이드 PNG 는 렌더링 중에만 있다가
[s12_video.py:149](pipeline/s12_video.py#L149) 에서 지워집니다. 영상이 없으면
상자를 얹을 그림이 없습니다.

★ **7.2 에서 발음을 확정합니다.** 장마다 듣고 고치면 그 장만 다시 합성합니다.
전체를 다시 돌리지 않습니다.

★ **7.4 — 발음을 고쳤으면 영상을 한 번 더 굽습니다.** 모션은 **완성 mp4 의
오디오를 그대로 복사**합니다(`-c:a copy`). 옛 mp4 위에 모션을 얹으면 고친 장만
옛 발음으로 남습니다. 하나도 안 고쳤다면 건너뜁니다.

★ **7.3 은 사람과 앱이 나눠 집니다.** 상자를 어디에 걸지는 사람이 정하고,
그 상자가 **어느 말에 떠야 하는지**는 앱이 상자 안 글자를 읽어 대본과 맞춥니다.
화면 위치가 곧 말하는 차례는 아니기 때문입니다 — 19장은 31장 중 25장이
좌우로 놓여 있어 위→아래 정렬로는 차례가 정해지지 않았습니다.

## 핵심 개념

### 화면은 여섯 — 순서가 곧 규칙이다

```
새 발표   좌표(레포·영상·사이트·참고자료) → 설문 → 기획서
현황판    무엇이 남았나 · 모든 단계 실행          ← 위층(패널)
목차      장 순서·제목·유형 확정 · 빈 장 끼우기 · JSON 입출력
초안      판단·문구·대본을 한 번에 → 전체를 한 판에 놓고 읽는다
수정 유형  슬라이드 텍스트 / +삽입 이미지 / +삽입 영상
덱        음성 · 자막 · 전체 · 굽기
```

**넓게 잡고 좁혀 들어간다.** 목차로 뼈대를, 초안으로 살을 한 번에 붙이고,
전체를 읽으며 고칠 곳만 골라 유형 화면으로 들어간다. 마지막에 덱에서 겉을
돌린다. 장 하나씩 완성해 나가면 25장에 75번을 눌러야 하고, 무엇보다
**나란히 놓고서야 보이는 것**(중복·빈 곳·흐름)을 영영 못 본다.

**목차가 앞인 것이 핵심이다.** 목차는 지금 고치면 공짜고, 확정한 뒤에 고치면
문구·판단·대본·음성을 전부 다시 돌려야 한다. 그래서 비싼 단계로 내려가기 전에
문을 하나 둔다.

### 원고 JSON — **파일은 한 종류다**

칸은 언제나 다 있고, 아직 안 만든 것은 **빈 문자열**이다. 그래서 세 가지 쓰임이
같은 파일 하나로 된다:

```
빈 틀만 뽑아 밖에서 채워 오기      목차 화면에서 내보내기 → 대본 칸이 비어 있음
다 만든 뒤 고쳐 오기               초안 화면에서 내보내기 → 다 차 있음
발표를 통째로 되살리기             11_완성/<slug>-원고.json
```

넣는 곳도 아무 데나 된다 — **파일에 무엇이 들었는지는 앱이 본다.** 대본이 하나라도
들어 있으면 통째로 넣고, 뼈대뿐이면 화면에 올려 보고 확정하게 둔다.

```jsonc
{ "deck_title": "…",
  "sections": [{ "id": "personal", "title": "개인(전문가) 회원 화면" }],
  "slides": [{
    "no": 4, "section": "personal", "kind": "feature", "media_kind": "text_image",
    "title": "내 경력이 어디까지 왔는지 한 화면에서 볼 수 있습니다",
    "note": "", "video_id": null, "evidence_hint": "",
    "body": "경력 건수·프로젝트·증빙 서류 상태에 역량 링 차트까지.",
    "narration": {
      "srt_text": "개인 대시보드입니다. 위쪽에 …",   // 화면 자막(원문)
      "text":     "개인 대시보드입니다. 위쪽에 …"    // TTS 가 읽는 것(발음)
    }
  }] }
```

`narration.text` 는 발음 교정본이다 — `ODA` 를 `오디에이` 로 적어 두면 그렇게
읽는다. 비우면 `srt_text` 를 그대로 읽는다. 길이는 글자수에서 추정하고, 합성이
끝나면 실측으로 다시 잡힌다. `media_kind` 는 `text · text_image · video · code`
넷뿐이고 모르는 값은 `text` 로 내려앉는다. 번호는 무시하고 순서대로 다시 매긴다.

**크기는 걱정하지 않아도 된다.** 40장짜리가 46KB — 장당 1.2KB다. 텍스트뿐이라
음성·이미지는 안 들어간다.

**넣으면 손편집은 버려진다.** 손편집 키는 옛 번호를 가리키는데 번호가 통째로
바뀌므로, 남겨 두면 엉뚱한 장에 옛 자막이 붙는다.

### 하나의 연속 번호, 레인은 섞인다

```
S2b   번호 + 레인 배정      1 텍스트 · 2 영상 · 3 텍스트+그림 · 4 텍스트 · 5 영상 …
  ↓   레인별로 따로 채움    S3 캡션 · S3b 그림 · S5 판단 · S6 대본
S8    번호순으로 다시 모음
  ↓
S9    하나로 렌더링         1 … 37
```

레인이 존재하는 이유는 **만드는 비용이 다르기 때문**입니다. 텍스트는 쉽고, 영상과
그림은 오래 걸립니다. 그래서 따로 만들고 번호로 합칩니다.

레인이 연속 구간으로 뭉치면 발표가 지루해집니다 — 코드가 뭉침을 검사해 경고합니다.

### 세 가지 텍스트는 서로 다르다

| | 무엇 | 만드는 곳 |
|---|---|---|
| 슬라이드 문구 | 화면에 박히는 글 | S7 (문체 선택 가능) |
| 자막 `srt_text` | 입으로 말하는 것의 원문 | S6 |
| 발음 `narration_text` | TTS 가 소리 내는 표기 | S6 |

`2vCPU` 는 자막엔 그대로 두고 발음만 `투 브이씨피유` 로 바꿉니다.

### 승인 게이트 3단

```
1차 화면   슬라이드 면이 이대로 나가도 되는가
2차 대본   자막·발음이 이대로 읽혀도 되는가
3차 무음   (영상 장만) 원본 소리를 죽이고 내레이션만 얹어도 되는가
```

37장을 한 번에 다 볼 수 없으므로 어디까지 봤는지가 파일에 남습니다.

### 손편집이 항상 이깁니다

`10_덱/deck.overrides.json` 이 스테이지 결과 **위에** 얹힙니다. S5·S6·S7 를 다시
돌려도 손으로 고친 자막·문구·✓ 는 살아남습니다.

### 여러 버전

같은 재료로 광고체 한 벌, 개조식 한 벌을 만들어 두고 비교할 수 있습니다.
버전 = 스테이지 캐시 + 손편집 한 벌. 원본(영상·레포)은 복사하지 않습니다.
되돌리기 전에 지금 것을 자동으로 한 벌 뜹니다.

### 기획서는 양방향

처음에는 툴이 `00_기획/prd.md` 를 만들어 줍니다. 익숙해지면 그 파일을 직접 써서
넣으면 됩니다 — 고쳐 두면 다음 실행에서 **고친 내용이 이깁니다.** 코드 변경 없이
접점이 파일 하나입니다.

## 화면 규칙

> **새 화면을 만들 때 이 둘은 협상 대상이 아닙니다.**
> 지키면 화면끼리 같은 물건으로 보이고, 어기면 매번 처음 쓰는 앱이 됩니다.

### 규칙 1 — 2층. 목록은 뜨고, 작업은 바닥

```
   ┌──────────────────────────────┐
   │  위층 — 떠 있는 패널          │   현황판 · 프로젝트 · 워크스페이스
   │  고르고 닫는 곳               │   Esc · 바깥 클릭으로 닫힌다
   └──────────────────────────────┘
   ┌──────────────────────────────┐
   │  바닥 — 일하는 곳             │   시작 · 목차 · 텍스트 · 이미지 · 영상 · 덱
   │  글자를 치는 곳               │   패널을 열고 닫아도 살아 있다
   └──────────────────────────────┘
```

가르는 기준은 하나입니다 — **저장 안 된 글자가 있는가.**

자막을 고치다 `Esc` 를 누르면 닫히는 곳에 그 입력칸을 두면 안 됩니다. 그래서
목차·대본·이미지·영상은 전부 바닥입니다. 반대로 목록과 현황은 위층입니다 —
닫으면 보던 자리로 그대로 돌아와야 하는데, 바닥이면 화면이 통째로 갈아치워져
돌아올 자리를 잃습니다.

부수 효과가 하나 더 있습니다. 패널을 열어도 바닥은 언마운트되지 않으므로,
**몇 분 걸리는 단계의 진행과 타이핑하던 내용이 살아남습니다.**

### 규칙 2 — 누르면 시계가 돈다

이 앱은 한 번 누르면 2~3분씩 가는 단계가 많습니다. 그동안 화면이 안 바뀌면
사람은 멈춘 것으로 읽고 **다시 누릅니다** — 같은 단계가 두 번 돌면 돈이 두 배로
나갑니다. 그래서 실행하는 자리는 예외 없이 이 셋을 같이 보여 줍니다.


무엇을 하는지도 같이 말합니다. 레포를 읽는 단계는 파일 이름까지 올라옵니다
(`adm/exam_qna_form.php 읽는 중`) — 모델이 툴을 쓸 때마다 흘려보냅니다.

구현은 [`static/js/runner.js`](static/js/runner.js) **한 곳뿐**입니다.

```js
await runSteps(["s10-tts", "s11-audio"], {
  btn, label,                      // 누른 버튼이 그대로 시계가 된다
  names: {"s10-tts": "음성 합성"},   // 사람이 읽는 이름
  onStep: (text, at) => { ... },   // at = {completed, total, step, sec}
  onLog:  (lines) => { ... },      // 새로 늘어난 줄만
  onDone: () => { ... },
});
```

폴링 루프를 화면마다 따로 두지 않습니다. 예전에 네 벌이 흩어져 있었고 고칠
때마다 한 군데씩 빠뜨렸습니다.

## 화면

### 덱 — 보기 둘

```
전체   37줄을 세로로 훑는다. 순서·누락·누적 시각을 본다
번호   그 장 하나만 크게. 실제 슬라이드 면 + 자막 + 발음 + 영상 확인기
```

세로 한 판으로만 두면 10장 넘어가는 순간 관리가 안 됩니다. 그래서 상단에
`전체 · 1 · 2 · … · 37` 번호 탭을 두고, 고칠 때는 한 장으로 들어갑니다.

슬라이드 실물은 최종 렌더러를 iframe 으로 띄웁니다 — 여기서 OK 한 면이
그대로 산출물이 됩니다.

### 전체 길이

맨 위에 **몇 분짜리인지**가 있습니다. 실측(합성된 wav)과 추정(대본 글자수)을
구분해 보여 주고, 목표 길이(10·20·30·40·60·120분)를 정하면 남거나 모자란 만큼을
표시합니다. 합성이 끝나면 **실측으로 추정 계수를 자동 보정**합니다.

## 슬라이드 페이지

- `←` `→` `Space` 넘김 · `Home`/`End` 처음·끝 · `C` 자막 토글 · 클릭·스와이프
- **첫 장에 `▶ 시작` 버튼**이 필요합니다. 브라우저가 제스처 없이는 소리를 안 냅니다
- **영상은 재생 중에만 커집니다.** 시작하면 펼쳐지고, 끝나면 제자리로 돌아와
  내레이션이 이어집니다
- 영상은 항상 무음입니다 — 소리는 내레이션 트랙이 냅니다
- 폰트는 쓰인 글자만 서브셋해 인라인합니다 (Pretendard 3종 1.8MB → 203KB)

## 필요한 것

| | 없으면 |
|---|---|
| Python 3.10+ | 안 돕니다 |
| Claude Code 로그인 | Claude 단계가 안 돕니다 |
| ffmpeg | 프레임 추출·영상 변환이 안 됩니다 |
| `gh` CLI | 레포 수집이 안 됩니다 (영상만으로도 덱은 나옵니다) |
| voicewright + Supertonic-3 | 음성이 안 나옵니다. 덱·자막·큐시트는 전부 나옵니다 |

TTS 는 `showcase.config.json` 의 `tts` 에 경로를 적어야 돕니다:

```json
"tts": {
  "engine": "voicewright",
  "python": "…/.venv/Scripts/python.exe",
  "voicewright_dir": "…",
  "assets_dir": "…/assets"
}
```

성우 파일을 `07_음성/005.wav` 처럼 번호로 넣어 두면 **그 장은 합성하지 않습니다.**

## 하지 않는 것

- **다른 앱과 프로세스를 잇지 않습니다.** 이미지는 별도 앱(ChatGPT OAuth)이 만들고,
  접점은 `09_이미지/` 폴더 하나입니다. 인증 주체가 다른 것을 코드로 이으면 사고가 납니다.
- **LAN 공유를 하지 않습니다.** 이 앱은 호스트의 Claude 구독으로 돕니다.
- **API 키를 쓰지 않습니다.** 환경변수의 `ANTHROPIC_API_KEY` 는 무력화합니다.
- **에이전트가 네트워크를 만지지 않습니다.** `Bash`/`Write`/`WebFetch`/`WebSearch` 차단,
  레포는 호스트가 clone 하고 Claude 는 `Read`/`Grep`/`Glob` 만 씁니다.
